# dsh-stage-router 路线图

> 设计：`docs/superpowers/specs/2026-09-25-stage-router-design.md`（已按 dsh 0.1.7 修订）
> 目标版本：`@deepseek-ai/dsh@0.1.7-rc.2`，所有 `@deepseek-ai/*` 开发依赖都锁这个精确版本。

## 总览

| 期 | 目标 | 依赖 | 完成标准 | 详细计划 |
|---|---|---|---|---|
| 0 | 技术验证：设计依赖的 dsh 接口真实可用 | 无 | 六项验证都有结论（通过 / 改用回退方案 / 需本地复核），设计和第 1 期计划已按结论回改 | `2026-09-25-phase0-spikes.md` |
| 1 | 核心能力：只写配置就能按阶段切模型 | 第 0 期第 1、2、3、4 项 | 单元测试和无界面集成测试全绿；本地 `dsh web` 装上后能在选择器里选方案并看到阶段切换 | `2026-09-25-phase1-core.md` |
| 2 | 阶段内分档、子 agent 路由 | 第 1 期 | 分档和子 agent 的单元测试 + 集成测试全绿 | 第 1 期完成后再写 |
| 3 | 对话内展示：小标签、每轮摘要、`/stage` 命令、远程服务 | 第 1 期；第 0 期第 5 项 | Web 端手动验证通过 | 第 2 期完成后再写 |
| 4 | 可视化编辑器，含「试一试」 | 第 3 期的远程服务 | Web 端手动验证通过 | 第 3 期完成后再写 |

第 2 期和第 3 期互不依赖。第 1 期完成后，可以按需要调换顺序。

## 第 0 期：技术验证

在云端容器里用 npm 版 dsh 跑，无界面，接一个假的 LLM 服务商。需要看界面的项目留给本地复核。

| # | 验证什么 | 失败时的回退方案 |
|---|---|---|
| 1 | 根作用域 `prepend` 的 `agent/request` 改写能胜过 model-selection，且会话记录的请求头是真实模型 | 改为在 `agent/created` 里按 agent 以 `prepend` 注册；再不行就让虚拟服务商的 `stream()` 自己转发（放弃"请求头是真实模型"带来的好处，按 skill-vault 的方式修补历史） |
| 2 | 按 agent 以 `prepend` 注册的 pre-step 能过滤掉 `source.kind==='model-selection'` 的提示 | 不过滤，改为在本插件的提示里说明原因（提示会重复，但不影响功能） |
| 3 | 自定义 `source.kind` 的提示消息能被投影读到，会话重新加载后仍能读到、不报错 | 状态改存 `~/.dsh/stage-router/state.json`（按 sessionId 保存） |
| 4 | 在 `agent/inbox/claimed` 里调用 `ctx.planMode.set`，当步就生效；计划批准能在 pre-step 里识别 | 联动推迟到下一次 pre-step；批准改为通过 `exit_plan_mode` 的工具结果识别 |
| 5 | 插件能注册 `/stage` 命令 | 只保留界面入口 |
| 6 | 虚拟模型声明支持图片后，带图片的消息能通过检查 | `resolveModel` 不填 `inputModalities` |

**风险**：第 1 项和第 3 项决定架构，要最先做。容器里跑不通无界面多轮会话时，改用 dsh 仓库自带的测试工具（test-support）在进程内启动。

## 第 1 期：核心能力

**范围**
- 配置结构和语义校验
- 虚拟服务商
- 状态机和判断器
- 四个核心钩子
- 计划模式联动
- 状态持久化

**风险**
- 判断器的提示词效果只能靠真实模型检验。集成测试用假服务商保证流程正确；提示词质量放到本地手动验证。
- 0.1.7 的插件配置存放位置和热更新（`loader/volatile-update`）行为，要在第 1 期的第一个任务里用实际运行确认。

## 第 2 期：分档与子 agent（任务清单）

- `engine/tiers.ts`：
  - 解析规划者写的 `[Tn][<档位>]` 标签；
  - 多个进行中的待办取最重一档；
  - 等待判断结果最多 1.5 秒，超时用 `default` 档。
- 分档判断：
  - 监听 `todo/write` 事件，只对新增或变化的待办调用判断器，每批最多 30 条；
  - 结果按待办内容的哈希缓存。
- `hooks/request.ts`：改写请求前先定档。
- `hooks/subagent.ts`：
  - 识别 `parentSession`，尊重显式指定的模型；
  - fork 出来的子 agent 跟随父会话；
  - 新建的子 agent 按 `[Tn]` 或判断器定档。
- 测试：
  - `tiers` 的单元测试；
  - 集成测试覆盖子 agent 开关的两种状态。

## 第 3 期：对话内展示（任务清单）

- `remote.ts`：
  - 最近 50 条决策记录；
  - 锁定、解锁阶段；
  - 按任务改档。
- `/stage <id>`、`/stage auto` 命令，注册方式取决于第 0 期第 5 项的结论。
- `client/StageChip.tsx`：挂在 `conversation.input.right` 插槽，通过 props 读 `stage-router` 投影。
- `client/TurnTail.tsx`：挂在 `conversation.chat.turnTail` 插槽。
- 客户端打包：`scripts/build-client.mjs`，以及 `package.json` 里的 `dsh.client` 字段。

## 第 4 期：可视化编辑器（任务清单）

- 开工前，先按 0.1.7 的设置服务（`describe` / `update`）和 `settings.plugins.tab` 插槽再核对一遍接口。
- 编辑器：
  - 方案列表，四个标签页（基本 / 阶段 / 转换 / 判断器 & 子 agent）；
  - 模型下拉的数据来自 `remote.session.modelCatalog()`；
  - 「试一试」通过远程服务实时调用判断器。
- 保存时把语义校验的错误定位到具体字段。
